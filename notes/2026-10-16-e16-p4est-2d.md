# 2026-10-16 E16：数组原型支持 2D P4estMesh

2026-10-16 计划的第 4 项。导师要 2D 和 3D 都有，E12 只做了 3D。

- 脚本：`experiments/e12_p4est_array.jl`（算例 `adv2d<T>`、`euler2d<T>`、`mhd2d`；只有 gather 路径，没有 `faces`/`trees`）
- 机器：同 E14；日志 S3 `2026-10-16-e14-e19-tpu/`

## 做法

- 和 3D 一样的 gather 写法：每个单元 4 个面（slot），每个面是 n 个节点的一条线；邻居的面值一次 gather 取整个面，
  再按朝向翻转。2D 只有两种朝向：同向或反向（Trixi 的 `:i_backward`，次单元的面节点倒着走）
- 体积分、逐点物理、CFL 时间步、`pw` 包装（MHD 的 `c_h`）都改成和维数无关（`length(p.Ja)` 个方向，逐点包装从参数个数
  推出维数），3D 的结果没变
- 网格信息照 Trixi 2D 的 delayed indexing 取，断言面节点编号和 Trixi 的面积分一致

## 结果

rhs! 对 Trixi（CPU 后端，t = 0.3 的精确解），max|du − du_Trixi| / max|du_Trixi|：

| 算例（`test_cuda_2d.jl` 的 elixir） | 网格 | Float64 | Float32 |
|---|---|---|---|
| `elixir_advection_basic.jl` | 8×8 树，256 单元，周期 | 8.1e-14 | 2.3e-5 |
| `elixir_euler_source_terms.jl` 弱形式 | 16×16 树，256 单元，周期 | 2.7e-13 | 1.1e-4 |
| 同上 FD（Kennedy–Gruber） | 同上 | 5.9e-13 | 2.1e-4 |
| `elixir_mhd_alfven_wave_combined_fluxes_nonperiodic.jl` | 64 单元，Dirichlet | 4.5e-14 | 1.8e-5 |

完整模拟（TPU v5e，Float32，l2 / linf 最大相对差）：

| 算例 | 步数 | 对 Trixi CPU Float32 | 对 GPU 测试参考值 | 参考：Trixi Float32 对 Float64 |
|---|---|---|---|---|
| 对流 | 18 / 18 | 1.5e-3 / 3.6e-2 | 2.2e-3 / 4.7e-2 | 6.2e-4 / 8.7e-2 |
| Euler 弱形式 | 229 / 229 | 3.9e-2 / 6.8e-2 | 1.9e-2 / 8.8e-2 | **1.8 / 0.68** |
| Euler FD | 229 / 229 | 4.1e-2 / 1.1e-1 | 4.6e-2 / 9.9e-2 | **1.5 / 0.77** |
| MHD | 36 / 36 | 9.9e-5 / 3.3e-3 | 4.5e-4 / 2.5e-3 | 1.7e-4 / 1.2e-3 |

- 全部"通过"，但 2D Euler 的误差（~1e-6）已经在 Float32 的地板上：**Trixi 自己 Float32 和 Float64 的 l2 差 1.5–1.8 倍**，
  GPU 测试的参考值本身也和 CPU Float32 差 5–14%；绝对差都远小于 atol（6e-5），所以这两行的"通过"说明不了多少，
  有意义的是 Float64 的 rhs! 对比（≤ 6e-13）。E7 也看到过 Float32 地板（≈ 3e-6）
- `host` 和 `trace` 两种循环结果一样

## 性能（TPU v5e，Float32）

100 万单元（1024×1024 树，n = 4，1677 万 DOF，周期），gather 路径（没有 2D 的砖形优化）：

| | 弱形式 | FD |
|---|---|---|
| rhs! | 227 ms | 229 ms |
| 一个 RK 步，`hoststep` | 1109 ms（0.98 × 5 rhs!） | 1187 ms（1.04 ×） |
| 一个 RK 步，`trace` | 1152 ms（1.02 ×） | — |
| 参考：E7 笛卡尔数组写法，同样 1677 万 DOF：切片 / 面 gather | 11.1 / 41 ms | 13.7 / 43 ms |
| 参考：A100 上 Trixi 原生 CUDA（E8，同一个 elixir、同一个网格） | 16.4 ms | 13.7 ms |

- gather 路径在 2D 比 E7 的切片写法慢 20 倍、比 E7 的笛卡尔 gather 版本也慢 5 倍：每个 slot 一次 gather（400 万个下标），
  TPU 的 gather 按下标收费（E6），再加上所有面的拼接、边界块拼接和朝向掩码。
  3D 里同样的问题靠 `faces`（砖形网格面通量直接从切片算）和布局解决了（E12：251 → 38.9 ms）；2D 还没移植这条路径
- 时间循环在 2D 没有 FD 的问题（`hoststep` 1.04×）
