# 2026-10-17 E20：2D 的砖形（`faces`）路径，包括周期方向

E16 的 2D 只有 gather 路径，100 万单元 rhs! 227 ms，比 E7 的笛卡尔切片写法慢 20 倍。这里把 3D 的砖形路径（E12 的
`faces`：面通量直接从切片算）改成和维数无关，并支持周期方向（E7/E8 的 2D 算例是周期的；E12 的砖形路径原来只能做非周期）。

- 脚本：`experiments/e12_p4est_array.jl`（`E12_OPTS=faces`，2D 和 3D 同一套代码）
- 机器：GCE TPU v5e `ct5lp-hightpu-1t`（机器镜像 `tpu-ubuntu-base`，europe-west4-b，按需），Julia 直接在主机上跑
  （`JULIA_PROJECT=/opt/trixi-env`），CPU 后端的检查和 TPU 的任务在同一台机器上同时跑
- 日志：S3 `2026-10-17-e20-e24/`（本地 `logs/` 同名目录）

## 做法

- 单元的全局坐标：先按面的连接关系做广度优先遍历（非周期的砖形网格，弯曲的也行）；不行的话（周期方向会绕回来）
  按单元中心排序（轴对齐的网格），再逐个面检查：每个方向要么全是边界、要么全是周期的绕回
- 周期方向：第 N 层和第 1 层之间的界面通量只算一次（第 N 层的 +a 法向），作为第 N 层 +a 面的通量、第 1 层 −a 面通量的相反数，
  和边界层一样用 `pad` 加上（没有 gather、没有拼接）
- 3D 的结果和原来一样（下面的检查）

## 结果

rhs! 对 Trixi（CPU 后端，t = 0.3），max|du − du_Trixi| / max|du_Trixi|：

| 算例 | 网格 | Float64 | Float32 |
|---|---|---|---|
| 2D `elixir_euler_source_terms.jl` 弱形式 | 16×16 树，周期 | 2.7e-13 | 1.1e-4 |
| 同上 FD | 同上 | 5.9e-13 | 2.6e-4 |
| 3D `elixir_euler_source_terms_nonperiodic.jl` 弱形式 / FD（回归检查） | 64 单元，Dirichlet | 1.3e-13 / 1.3e-13 | 4.1e-5 / 7.0e-5 |

性能：100 万单元（1024×1024，n = 4，1677 万 DOF，周期），TPU v5e，Float32：

| | rhs! 弱形式 | rhs! FD | 一个 RK 步（`hoststage`）弱形式 / FD |
|---|---|---|---|
| E16 gather 路径 | 227 ms | 229 ms | 1109 / 1187 ms |
| **`faces`** | 20.1 ms | 29.3 ms | 104.7 / 160.1 ms |
| **`dim,fdloop,faces`** | **18.3 ms** | **27.2 ms** | **93.3 / 141.7 ms** |
| 参考：E7 笛卡尔切片写法（TPU） | 11.1 ms | 13.7 ms | |
| 参考：A100 上 Trixi 原生 CUDA（E8，同一个 elixir、同一个网格） | 16.4 ms | 13.7 ms | |

- 砖形路径在 2D 快了 12 倍（227 → 18.3 ms）；还比 E7 慢 1.6–2 倍（E7 是专门的笛卡尔写法，没有度量项）
- 弱形式已经和 A100 上的 Trixi 原生差不多（18.3 vs 16.4 ms），FD 慢 2 倍
