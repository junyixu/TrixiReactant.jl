# 2026-10-16 E15：数组原型跑 GLM-MHD（非守恒项、每步变化的 c_h）

2026-10-16 计划的第 3 项。E12 的主要说法是"物理部分直接 broadcast Trixi 的逐点函数，换方程不用重写"，之前只在 Euler 上验证过。
GPU 测试 2D、3D 都有 `elixir_mhd_alfven_wave_combined_fluxes_nonperiodic.jl`：9 个变量、Powell 非守恒项（"combined"
通量）、HLLE 面通量、Hindenlang–Gassner 体通量，`GlmSpeedCallback` 每步改清除速度 `c_h`。

- 脚本：`experiments/e12_p4est_array.jl`（算例 `mhd`、`mhd2d`）
- 机器：同 E14；日志 S3 `2026-10-16-e14-e19-tpu/`

## 要补的东西（都在原型里，不改 Trixi）

1. **combined 通量返回 (flux_left, flux_right)**：每个单元面（slot）用自己的状态作 u_ll、自己的外法向，取左边那一半。
   Trixi 给次单元的是 $-f_{right}(u_{主}, u_{次}, n)$，对这个算例 $f_{left}(u_{rr}, u_{ll}, -n) = -f_{right}(u_{ll}, u_{rr}, n)$，
   只差舍入。体积分只用左边那一半（和 Trixi GPU kernel 的 FullSweepGlobal 一样）。边界上 elixir 自己定义的
   `BoundaryConditionDirichlet` 方法也是取左边那一半，和 slot 的做法相同
2. **按值分支的函数**：traced 的值不能决定 `if`。`Trixi.ln_mean`、`inv_ln_mean`（`if f2 < 1e-4`）和 `FluxHLL`（按波速选
   左/右/HLL）要两边都算再 `ifelse`。Trixi 自己已经给 SIMD 类型写了无分支版本的 `ln_mean`，照着加了 traced 版本
3. **每步变化的 `c_h`**：Trixi 的方程结构体字段必须是 `Real`（`IdealGlmMhdEquations3D{RealT <: Real}`），traced 数
   不是 `Real`，放不进去；放进类型参数又会每步重编译。**MHD 通量对 `c_h` 是仿射的**（`c_h` 只线性出现在通量里，波速不含它），
   所以每个通量算两次：方程里 `c_h = 0` 和 `c_h = 1`，$f = f_0 + c_h (f_1 - f_0)$，`c_h` 作为运行时参数传进来。
   XLA 会合并两次计算的公共部分。`c_h` 按 `GlmSpeedCallback` 算：$c_h = \text{glm\_scale} \cdot \Delta t_{c_h=1} / \Delta t_{\mathrm{CFL}}$，
   $\Delta t_{c_h=1} = \mathrm{cfl} \cdot 2 / (n \cdot 3 \max J^{-1})$（网格常数，CPU 上算一次），用钳到 `tend` 之前的 CFL 时间步
4. **世界年龄**：elixir 在 `trixi_include` 里定义通量和 `combine_conservative_and_nonconservative_fluxes` 的方法；
   在那之前就开始运行的函数看不到它们（Trixi 自己的 rhs! 也会走默认的 `False`，直接报 MethodError）。
   `trixi_include` 之后的部分用 `Base.invokelatest` 继续

## 结论

- 换方程确实不用重写通量：Trixi 的 MHD 通量、波速、初值/边界函数原样 broadcast
- 但有三类 Trixi 代码数组写法（以及任何 tracing 方案）都会碰到，值得报给 Trixi：
  按值分支的函数（`ln_mean`、`FluxHLL`；Trixi 已有 SIMD 无分支版本，可以统一）、方程结构体只接受 `Real`
  （随时间变化的参数，例如 `c_h`，没法作为 traced 值传进去）、elixir 里定义的方法与世界年龄
- 仿射分解只对 `c_h` 这种线性出现的参数成立；更一般的做法要 Trixi 的方程允许非 `Real` 的字段类型
