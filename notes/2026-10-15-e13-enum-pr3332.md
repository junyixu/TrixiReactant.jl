# 2026-10-15 E13：Trixi PR #3332（`NodeIndex` 枚举代替 `Symbol`）和 Reactant

PR #3332（ranocha，draft，基于 `main`，0.18.0-DEV）把 `node_indices` 里的 `Symbol` 换成 EnumX 的
`NodeIndex.T`（UInt8），`index_to_start_step_2d/3d`、`indices2direction`、`surface_indices` 都改成比较枚举。
E3 的第二个卡点（`Symbol` 元组数组、kernel 里 `===` 比较符号）和 E4 的 `Int8` 绕过正是为这个做的。

- 镜像：TrixiDocker 分支 `feat/docker-enum`（`a562d99`，Dockerfile 新增 `TRIXI_URL`/`TRIXI_REV` 构建参数，在主环境装好后把
  Trixi 换成 git 版本；0.18.0-DEV 不满足 `[compat]` 和 Trixi2Vtk 对 0.17 的要求，所以去掉这两个），
  CI run 38751987438 构建了 `:enum` 和 `:enum-tpu`；容器里 `Trixi 0.18.0-DEV`，`NodeIndex` 有定义
- 跑在 TPU VM 的 CPU 后端（容器不加 `--privileged`），raise 和 E4 一样走 CUDA kernel → MLIR → StableHLO
- 日志：S3 `2026-10-15-enum-pr3332/`

## E4（逐个 kernel 重放并 raise），`:enum-tpu` 对比 `:tpu`（Trixi 0.17.14 + E4 原来的 `Int8` 绕过）

- PR 之后**不需要替换 Trixi 的任何方法**（E4 原来给 5 个 index helper 加了 `IdxCode` 方法）。只剩一件事：
  元组数组不能做 XLA buffer，要换成整数数组 `(N, size...)` 加一个取下标时拼回元组的小容器（`EnumTuples`）
- **Reactant bug**：这个整数数组用 `UInt8`（枚举本来的类型）当 kernel 参数时，所有带它的 kernel 都报
  "operand and result shapes must match except for the innermost dimension of the shape with the smaller element type.
  Got: 'tensor<144x2x3xui8>' and 'tensor<864xi8>'"（Reactant 0.2.291 处理无符号 8 位多维数组参数的 bitcast 有错）。
  改成同样大小的 `Int8` 存（按位 reinterpret 回枚举）就好
- 改成 `Int8` 后，11 个 case 的每个 kernel 结果和 `:tpu` 镜像**完全一样**：界面、边界 kernel（2D/3D
  `prolong2interfaces_and_calc_interface_flux`、`prolong2boundaries`、3D `calc_boundary_flux`）照样 raise 且正确，
  其余失败的（体积分、`compute_coefficients`、有源项的面积分、2D MHD 边界的 `sinpi`、3D advection / FullSweepGlobal
  段错误）原因和符号无关，PR 前后一样；2D advection 界面 kernel 的 NaN 也还在

## E3（整个 rhs! 过 Reactant，2D P4est advection）

- 0.17.14：`trixi_adapt(ConcreteRArray, Float32, semi)` 就失败（符号数组）
- PR + 上面的整数容器（这里要是 `DenseArray{NTuple{N, NodeIndex.T}}` 的子类型，因为 PR 的容器类型参数这样要求）：
  `trixi_adapt` **成功**，下一个卡点是 `LobattoLegendreBasis` 的类型参数要求 `<: AbstractMatrix{RealT}`，
  而 Reactant 追踪时数组的 eltype 是 `TracedRNumber`（E4 已经遇到过，用 `DeviceMatrix` 包一层）
- 加上 `DeviceMatrix`（`reactant_overrides.jl`）之后：基函数没问题了，下一个是同一类问题出在
  `P4estElementContainer`（类型参数要求 `DenseArray{RealT}`）；把 semi 放进闭包而不是当参数时，
  Reactant 自己报 `UndefVarError: _derived_array not defined in ReactantCUDAExt`（把 Trixi 的
  `ReshapedArray` 状态转换成 kernel 参数时，`ReactantCUDAExt.jl:589`），是 Reactant 的 bug
- 所以整个 rhs! 走 Reactant 还要：Trixi 容器的类型参数放宽到能装 Reactant 数组（或者 Reactant 追踪时保留 eltype），
  加上 Reactant 修这个 bug。数组路线不需要这些，没有再往下追

## 结论

PR #3332 解决了符号的问题：Trixi 的 index helper 原样就能在 raise 后的 kernel 里用。要让 Reactant 收下这些数组，
还需要一个"元组数组 → 整数数组"的小适配（可以放进 Trixi 的 Reactant 扩展或 `trixi_adapt` 的规则里），
并且要避开 Reactant 对 `UInt8` 参数的 bug（或者 PR 用 `Int8` 做枚举的基础类型）。
