# 2026-10-17 E23：Pallas 写的 flux differencing 体积分

E12 的 rhs! 在 XLA 里每次要读写 78–110 遍状态大小的数组（理论上约 2.5 遍）；E19 验证了 JAX lower 的 Pallas kernel 能嵌进
Reactant 程序。这里把 3D flux differencing 体积分（Kennedy–Gruber，弯曲单元的度量项）写成一个 Pallas TPU kernel，
所有中间量留在 VMEM 里，HBM 上只读一次 u 和 Ja、写一次结果。

- 脚本：`experiments/e23_pallas_fd.py`（kernel、纯 JAX 的对照和计时、lower 成 StableHLO 文本），
  `experiments/e12_p4est_array.jl` 的 `E12_OPTS=pallas`（`Ops.hlo_call` 嵌进 rhs!，文本文件由 `E23_PALLAS_MLIR` 给出）
- 机器：GCE TPU v5e `ct5lp-hightpu-1t`（机器镜像 `tpu-ubuntu-base`：`/opt/jax-env` 里 jax 0.11.0，
  `/opt/trixi-env` 里 Reactant 0.2.291）
- 日志：S3 `2026-10-17-e20-e24/`

## kernel

- 输入：u (5, n, n, n, E)、Ja (9, n, n, n, E)（Ja^d 的第 j 个分量在 3(d−1) + j）、D_split (n, n)（放在 SMEM），
  输出 V (5, n, n, n, E)；按单元分块（每块 B 个单元，网格 E/B）
- 每个节点先算一次原始变量；对每个方向 d、每个伙伴节点 ii 算 Kennedy–Gruber 两点通量（法向取两点 Ja^d 的平均），
  乘 D_split[i, ii] 累加 —— 和 E12 的 `volume_fd_unrolled` 同样的数学
- 两种写法：`iota`（系数用 iota + select 沿节点维度铺开，结果和 XLA 版逐位相同）、`slab`（按输出节点层、标量系数、
  跳过 D_split 的零对角，累加到输出 ref）

## 结果

纯 JAX，TPU v5e，26 万单元（1677 万节点），Float32：

| B | `iota` | `slab` | 同样的数学用 jnp（XLA） |
|---|---|---|---|
| 128 | 3.43 ms | 3.38 ms | 27.6 ms |
| 256 | 3.01 ms | 2.60 ms | |
| 512 | 2.99 ms | 2.25 ms | |
| 1024 | VMEM 不够 | **2.19 ms** | |

- **比 XLA 快 12.6 倍**；按最少的读写（读 u、Ja，写 V，19 个状态大小的数组）算是 570 GB/s，接近 HBM 带宽
- 和 XLA 的差：`iota` 0（逐位相同），`slab` 1.9e-7（求和顺序不同）

嵌进数组原型（砖形路径 `dim,faces`，`slab`，B = 512，26 万单元 = E12 的 v4 网格）：

| | XLA（E14 v4，`dim,fdloop,faces`） | Pallas 体积分 | Pallas，度量项预先排好（`p.Jall`） |
|---|---|---|---|
| rhs! 对 Trixi（cart2，Float32） | 7.0e-5 | 5.5e-5 | 5.5e-5 |
| rhs! FD | 55.8 ms | 34.2 ms | **32.3 ms** |
| 一个 RK 步（`hoststage`） | 282.6 ms | 175.2 ms（1.02 × 5 rhs!） | **163.5 ms（1.01 ×），快 1.73 倍** |
| 每次 rhs! 的读写（profile） | 36.7 GB | 19.3 GB | 17.0 GB |

- FD 的时间步现在比弱形式（197 ms）还快
- profile（Pallas 版）：逐元素 kernel 20.1 ms / 12.2 GB、其他（含 Pallas kernel）8.0 ms、转置 5.8 ms / 4.2 GB —— 剩下的是面、
  源项和布局转换，体积分已经不是瓶颈
- 度量项（9 个状态大小的数组）每次 rhs! 都拼成 kernel 的输入是浪费：在 setup 里排好一次，rhs! 再快 2 ms

## 结论

- 手写 TPU kernel 是缩小 3D 差距的有效办法：体积分本身快 12.6 倍、接近带宽，整个 FD 时间步快 1.73 倍
- kernel 只能在 TPU 上用，物理（通量）要在 JAX 里再写一遍；剩下的面积分同样可以写成 kernel
